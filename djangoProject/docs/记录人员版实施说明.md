# 记录人员版实施说明

本版以 `pics/图片索引与说明.md` 中 21 张原型页面为业务依据。历史快速评审版中的多人线上流转规则已由记录人员代录规则替代。

## 首次使用与权限迁移

1. 管理员在 `/admin/` 创建记录账号；普通记录员不需要工作人员权限。
2. 项目成员增加该账号的“记录人员”角色。已有开发、测试等业务角色保留查看权限，不自动升级写权限。
3. 业务负责人、确认人和资料提供人直接录入姓名或群昵称，无需额外创建账号。
4. 需求默认“仅追加进展”，实际业务进度发生改变时选择“同时更新”；返工时明确选择新轮次。
5. 资料缺失可以先保存。上传截图后还需填写确认人、明确结论、原意摘要并核对。完成的需求仍可补旧环节资料。
6. API 日报进入待核对；确认原始资料后勾选已核对。修改已有数据时填写更正原因。

迁移 0002 新增记录模型，0003 回填历史业务姓名，0004 增加金额校验。历史账号外键、处理记录和附件仍保留。旧材料不会自动算作已确认。记录和快照通过应用权限保持只读，不承诺防止数据库管理员直接修改。

## 已有服务器升级

服务器项目路径：`/opt/xj_project_management/djangoProject`。先同步本版代码。以下命令以既有 systemd 服务名 `xj-project` 为例；服务名不同须替换。

```bash
cd /opt/xj_project_management/djangoProject
sudo systemctl stop xj-project
# 停止写入后备份数据库；同时备份 media/、运行环境配置和当前代码版本。
cp -p db.sqlite3 "db.sqlite3.backup-$(date +%Y%m%d-%H%M%S)"
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py check
.venv/bin/python manage.py collectstatic --noinput
sudo systemctl start xj-project
sudo systemctl status xj-project --no-pager
```

迁移命令使用与服务相同的运行账户及环境变量。若升级失败，保持服务停止，恢复备份数据库和匹配的旧代码后再启动；不要直接把新数据库交给旧代码。SQLite 仍为现有默认数据库，部署大量并发写入前需配置支持行锁的数据库。

Nginx 静态目录必须有末尾 `/`，与 `collectstatic` 输出对应：

```nginx
location ^~ /static/ {
    alias /opt/xj_project_management/djangoProject/staticfiles/;
}
location / {
    proxy_pass http://127.0.0.1:8005;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
client_max_body_size 25m;
```

多文件请求总大小受 Nginx 限制。网页生产配置使用 `DJANGO_DEBUG=0`、固定 `DJANGO_SECRET_KEY`、`DJANGO_ALLOWED_HOSTS=project.xjdev.one` 和 `DJANGO_CSRF_TRUSTED_ORIGINS=https://project.xjdev.one`。若 HTTPS 在 Nginx 终止，需在确认应用只通过受信代理访问、代理覆盖协议头的前提下配置 Django 受信代理协议头，避免 HTTPS 重定向循环。不能通过关闭 CSRF 来解决代理配置问题。

## 运营接口协议

在“运营数据 → 接口接入”创建项目接口，保存页面仅展示一次的 Token；丢失时停用旧接口并重新创建。此 Token 只允许写入对应项目的待核对日报，不提供读取其他项目或批准数据的能力。

- `POST /api/operations/ingest/`
- `Authorization: Bearer <接口 Token>`
- `Content-Type: application/json`
- 最大 1 MB；每批 1–500 条。

```json
{
  "request_id": "channel-report-20260923-001",
  "rows": [
    {
      "day": "2026-09-23",
      "channel": "搜索渠道",
      "visits": 1200,
      "registrations": 35,
      "cost": "28.50",
      "revenue": null,
      "source": "渠道日报原始记录编号 123"
    }
  ]
}
```

日期使用项目统计口径对应的业务日。访问、注册必须为非负整数或 null；金额为非负十进制或 null，按 USD 记录。缺失字段为未知值，不补零。注册数不是跨渠道去重人数，收入不自动归因于单项需求。

同一接口、同一 `request_id` 的相同内容重试返回原结果，不重复插入。相同 ID 不同内容拒绝。不同批次遇到相同项目、日期和渠道时，比对原数据：相同数值不改变核对状态，不同数值保留原值并标记差异，候选值保留在历史快照中，需记录员人工核对。单批任意一条非法则整批不写入业务数据，错误留在同步日志。

成功响应含 `request_id`、`count`、`conflicts`、`status`；认证失败 401、请求非法 400。接口采用 Token 认证，只有此接口免 CSRF；网页表单继续使用 CSRF 校验。

当前实现是数据源主动推送，并未承诺已接通任何第三方平台，也未配置定时拉取任务。可由数据源自己的调度器按日或按小时推送。

## 报告口径与导出

报告支持项目周报、单需求档案和运营工作报告，可选择项目、日期范围与附件。预览即生成固定快照，归档后仍使用同一份数据；要反映新记录须重新生成报告。

进度按录入日期筛选；运营数据按统计日筛选；需求、审查、波动和资产状态是生成时的快照，不是历史期末状态重建。只汇总已核对数据，并提示缺失分项。报表保留核查与续费历史，PDF 含可读取截图，附件包包含原件、报告和快照；原文件丢失时会输出缺失清单。系统不开放附件删除入口，但外部存储删除仍可能导致历史附件缺失。

Python 依赖新增 ReportLab、Pillow 和 openpyxl。无需安装 Office 或前端构建工具。

## 验收

执行 `manage.py test tracker`，测试使用独立测试数据库。浏览器验收覆盖登录、工作总览、需求记录表单、运营统计及报告预览；检查非记录员不能提交、跨项目访问被拒绝。生产上线后另需核查 Nginx 静态文件路径、媒体备份及业务账号角色配置。

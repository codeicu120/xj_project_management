# 序程项目管理平台安装文档

## 1. 安装范围与目录

本文说明当前代码的本地安装、初始化、启动和验证。当前采用 Django 4.2.30、SQLite 和 Django 模板，不需要 Node.js、Redis 或独立数据库服务。本机已验证环境为 Python 3.9.6；使用其他 Python 版本时应重新执行本文的测试步骤。

仓库目录如下：

```text
xj_project_management/           Git 仓库根目录
├── README.md                    文档入口
├── .gitignore                   本地文件排除规则
└── djangoProject/               应用目录，下文命令默认在此执行
    ├── manage.py
    ├── requirements.txt
    ├── .env.example
    ├── djangoProject/           Django 配置、路由与服务入口
    ├── tracker/                 业务代码、页面、静态资源及测试
    └── docs/                   产品需求与安装文档
```

准备 Python、pip、venv 和 Git。安装依赖时需要访问 Python 包源。Git 仅保存源码，不包含已有账号、数据库、上传附件或虚拟环境；新安装必须重新迁移并创建账号。

## 2. macOS / Linux 安装

打开终端，从仓库根目录执行：

```bash
cd djangoProject
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

如果已经存在可用的 `.venv`，无需重新创建。后续命令直接使用虚拟环境中的 Python，不要求激活环境。

### 配置本地环境变量

默认配置可直接用于本地验收。为使重启后登录会话继续有效，建议生成并保存固定密钥。首次配置时执行下面两条命令；若 `.env` 已存在，直接编辑已有文件，不要覆盖：

```bash
cp .env.example .env
.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

将生成值填入 `.env` 的 `DJANGO_SECRET_KEY`，其余示例值可保持不变。然后在当前终端加载自己维护的 `.env`：

```bash
set -a
. ./.env
set +a
```

应用不会自动读取 `.env`。每次新开终端启动服务时都要重新加载，或者通过进程管理器设置相同环境变量。`.env` 不会进入 Git；`.env.example` 仅保存无真实密钥的配置示例。

### 初始化与启动

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py check
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

按提示输入管理员用户名、可选邮箱及密码；密码输入时终端不显示字符。保持启动终端运行，按 `Ctrl+C` 停止服务。

- 平台首页：<http://127.0.0.1:8000/>
- 系统管理：<http://127.0.0.1:8000/admin/>

## 3. Windows PowerShell 安装

从仓库根目录执行以下等效命令：

```powershell
cd djangoProject
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

在 PowerShell 中显式设置配置，无需激活虚拟环境：

```powershell
$env:DJANGO_DEBUG = "1"
$env:DJANGO_ALLOWED_HOSTS = "127.0.0.1,localhost"
$env:BUSINESS_TIME_ZONE = "Asia/Shanghai"
$env:MAX_ATTACHMENT_MB = "20"
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
# 将下一行的占位内容替换为生成值，并自行保存，以便后续使用相同密钥。
$env:DJANGO_SECRET_KEY = "替换为刚生成的随机密钥"

.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

这些环境变量只作用于当前 PowerShell 会话。Windows 步骤为对应命令说明，当前未在 Windows 环境实测。

## 4. 可选演示数据

在全新的本地验收数据库中，可以用演示初始化替代手动创建管理员：

```bash
.venv/bin/python manage.py seed_demo
```

命令创建 `demo` 超级管理员、三个示例项目、示例需求与 Bug，并在终端输出随机密码。请保存本次输出；仓库不包含通用演示密码。

- `demo` 已存在时不会重复导入，也不会修改原密码。
- `developer`、`tester` 默认无法登录；如需测试分角色流程，由管理员设置密码。
- 不要在正式业务库导入演示数据。若已有同名 `developer` 或 `tester`，请改用手工创建项目，不要依赖该命令合并账号。
- 忘记本地演示密码时执行 `.venv/bin/python manage.py changepassword demo`。

Windows 下将命令中的 `.venv/bin/python` 替换为 `.\.venv\Scripts\python.exe`。

## 5. 首次使用

1. 使用管理员账号登录 `/admin/`，创建业务账号并保持“有效”勾选。普通业务账号不需要“工作人员状态”。
2. 创建项目，配置项目成员及业务角色。同一成员可配置多个角色。
3. 打开平台创建需求，填写正文、验收标准、负责人、优先级和截止日期。
4. 进入需求详情，在处理窗口确认、退回、转交或补充记录。当前负责人及下一负责人需要具备相应环节角色。
5. 测试验收环节由测试负责人创建 Bug；开发负责人提交修复，测试负责人登记回归结果。
6. 按流程完成需求方验收、代码上传、代码审核及结项检查。已完成需求和旧轮次记录可继续追溯。

## 6. 配置项

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DJANGO_DEBUG` | `1` | `1` 为本地调试，`0` 为生产模式 |
| `DJANGO_SECRET_KEY` | 开发启动时临时生成 | 建议固定；生产模式必须提供 |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,testserver` | 逗号分隔的主机名，不填写协议、路径或端口 |
| `BUSINESS_TIME_ZONE` | `Asia/Shanghai` | 页面业务时间与截止日期计算时区 |
| `MAX_ATTACHMENT_MB` | `20` | 单个附件大小上限，使用正整数 |

数据库当前固定为应用目录下的 `db.sqlite3`。代码尚未提供数据库连接环境变量；改用 PostgreSQL 需要调整 `DATABASES` 并安装对应驱动，不能仅设置 `DATABASE_URL`。

## 7. 安装验证

```bash
.venv/bin/python -m pip check
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test tracker
```

预期系统检查无错误，迁移检查输出 `No changes detected`，业务测试输出 `OK`。当前包含 27 项测试，覆盖流程、权限、版本、附件、Bug 回归及通知。测试使用独立测试数据库，不以现有演示数据库作为测试数据。

手工验证：登录后打开工作台、项目、需求、Bug 和操作日志页面；创建需求并推进一个环节，检查时间线与通知；使用无项目权限的账号验证不能访问该项目记录。

## 8. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| `No module named django` | 使用 `.venv/bin/python` 执行，先安装 `requirements.txt` |
| 找不到 `manage.py` | 先进入仓库中的 `djangoProject/` 应用目录 |
| `no such table` | 执行 `manage.py migrate` |
| 8000 端口被占用 | 使用 `manage.py runserver 127.0.0.1:8001` 并访问 8001 端口 |
| `DisallowedHost` | 把实际访问的主机名加入 `DJANGO_ALLOWED_HOSTS`，重启服务 |
| 重启后需要重新登录 | 配置固定的 `DJANGO_SECRET_KEY`，每次启动加载同一个值 |
| 页面跳转 HTTPS 后无法访问 | 本地 HTTP 验收使用 `DJANGO_DEBUG=1`；生产模式要求 HTTPS |
| 没有项目或处理权限 | 检查账号有效状态、项目成员、角色及当前负责人 |
| 缺少目标环节角色 | 在项目后台给接收人添加对应角色，或选择其他负责人 |
| 找不到附件文件 | 数据库记录与 `media/` 必须一并迁移或恢复 |

## 9. 更新与数据备份

更新代码前停止写入并备份 `db.sqlite3`、`media/` 及私有配置；SQLite 数据库应在服务停止后复制。仅备份 Git 代码不能恢复业务数据。备份放在仓库外，避免误提交附件或配置。

更新后在应用目录执行：

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py check
.venv/bin/python manage.py test tracker
```

确认通过后重启服务。数据库迁移后的恢复应使用与备份匹配的代码、数据库和附件，不应仅回退代码。

## 10. 正式部署边界

本文命令完成本地安装和验收，不等于生产部署。生产环境需配置进程管理、WSGI/ASGI 服务、HTTPS、静态文件服务和备份。生产模式会开启 HTTPS 跳转与安全 Cookie；反向代理终止 TLS 时，需要根据实际可信代理设置 Django 的协议识别，当前代码没有自动配置该项。

静态资源收集命令：

```bash
.venv/bin/python manage.py collectstatic --noinput
```

生成目录为 `staticfiles/`。不要公开 `media/`，附件应通过平台鉴权下载路由访问。当前 `runserver` 仅用于开发；生产并发数据库、依赖维护状态及部署配置需要另行验证。

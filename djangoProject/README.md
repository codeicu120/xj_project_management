# 序程 · 内部项目管理平台

基于仓库中的《项目管理后台产品需求快速评审版》实现，使用 Django、服务端模板和 SQLite。无前端编译步骤，无外部 CDN 依赖。

详细步骤见 [安装文档](docs/安装文档.md)，包含 macOS / Linux、Windows、环境变量、数据库初始化与常见问题。

## 本地运行

```bash
cd djangoProject  # 如果尚未进入本目录
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
w
```

访问 http://127.0.0.1:8000/，系统管理入口为 `/admin/`。也可运行 `.venv/bin/python manage.py seed_demo` 创建演示账号和三个示例项目；命令输出随机密码，也支持 `--password` 显式设置。命令不会覆盖已存在的 demo 账号。演示中的 developer、tester 账号默认无可用密码，需要管理员配置后才能登录。

## 已实现

- 中文工作台：我的待办、逾期列表、需求总量、未关闭 Bug、项目进度及最近操作。
- 项目与角色：项目创建、详情、成员配置、七种业务角色、管理员账号与停用、项目归档。
- 需求固定 11 环节：提出、规范整理、确认、分配、开发、测试、需求方验收、代码上传、代码审核、结项检查、已完成。
- 确认、退回、转交、补充记录；标题、正文、优先级与截止日期变更；每次操作保存不可在界面修改的快照、责任人、操作人、接收人、时间与处理轮次。
- 退回增加轮次，保留旧结论与旧材料；不允许跳过环节，仅可退回上游。代码上传与审核独立留存，并检查提交编号一致。
- Bug 在测试验收环节创建，关联需求、测试记录及轮次；独立修复、指派、回归通过、失败重开及关闭后重开记录。
- 附件随处理记录保存；鉴权下载、强制作为附件下载，不公开 media 目录。未上传材料时提示并记录不完整，不阻断流程。
- 测试存在未关闭 Bug 时，通过必须填写风险放行原因。
- 需求按项目、环节、负责人、优先级、更新时间与文本筛选；Bug 按项目、严重程度、优先级、状态、发现版本、修复版本与文本筛选。
- 状态、字段、转交、项目成员与附件操作日志；站内通知与已读管理。账号及权限管理操作另由 Django 内置后台日志保留。

## 操作说明

1. 管理员在系统管理中创建独立账号，勾选“有效”允许登录。普通业务账号无需“工作人员状态”；停用时取消“有效”。
2. 创建项目，在项目后台的成员列表配置角色。同一成员可拥有多种角色；新建项目时所选成员默认是需求提起人，项目负责人默认获得全部业务角色，可按实际分工调整。
3. 新建需求。进入需求详情，在处理窗口选择操作、接收人并填写处理结论。
4. 当前负责人必须具备当前环节角色；下一负责人必须具备目标环节角色。管理员可代处理。项目负责人身份本身不绕过角色检查。
5. 开发完成后进入测试，测试负责人登记 Bug。开发提交修复编号、版本及说明，测试负责人登记回归版本、结论与可选截图。
6. 通过测试、需求方验收后，登记代码上传；代码审核需填写相同提交编号。结项确认后完成。
7. 需求调整通过“补充记录”或“退回”操作展开内容编辑区。旧快照可在时间线展开查看，旧附件继续可下载。

## 默认决策及边界

- “已完成”指结项检查完成；没有新增发布上线或上线验证环节。
- 业务时区默认 `Asia/Shanghai`，由 `BUSINESS_TIME_ZONE` 配置。
- 附件默认单个 20 MB，支持 `MAX_ATTACHMENT_MB` 配置。不限制文件扩展名，下载时不执行文件内容。未实现杀毒、总配额、自动清理或外部存储。
- Bug 严重程度：致命、严重、一般、轻微；优先级 P0–P3。测试负责人负责创建、回归、关闭和重开；当前开发负责人修复；测试负责人、分配负责人、项目负责人或管理员指派。
- 项目可归档，归档后业务记录只读。历史记录和附件不提供删除入口，默认永久保留；需求作废及保留年限待业务确认。
- 支持窄屏布局。逾期提醒在工作台实时计算，流转与 Bug 动作触发站内通知，不包含外部消息或定时邮件。
- 沿用初始项目 Django 4.2.30。当前适合本地运行和功能验收；正式上线前应评估并升级至受维护的 Django 版本，迁移到 PostgreSQL，并配置 HTTPS、静态文件、备份与访问网络边界。SQLite 适合本地演示；并发写入的正式运行应使用具备行锁的 PostgreSQL。
- 记录采用应用权限保护，不承诺防数据库管理员篡改。已完成需求不能改变正文、状态或责任人，只可追加说明。

## 配置与部署

参见 `.env.example`，环境变量需由 shell / 进程管理器注入。生产模式设置 `DJANGO_DEBUG=0` 并提供稳定的 `DJANGO_SECRET_KEY` 和 `DJANGO_ALLOWED_HOSTS`。未配置密钥时生产启动会失败；开发模式的临时密钥在重启后变化，原登录会话需重新登录。生产模式启用 HTTPS 跳转及安全 Cookie，须通过 HTTPS 访问。

不要把演示账号用于正式环境。不要通过 Web 服务器直接公开 `media/`；下载统一走鉴权路由。正式启动使用 WSGI/ASGI 服务器；开发 `runserver` 不作为生产服务器。`collectstatic` 后由服务器提供 `staticfiles/`。

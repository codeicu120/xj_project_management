# 序程 · 产品与运营工作记录平台

基于 `pics/` 的 8 个模块、21 张页面原型实现。使用 Django、服务端模板和 SQLite，无前端编译步骤。

本版采用**专职记录人员代录**：业务负责人、需求提起人、群组确认人和资料提供人直接填写姓名或群昵称，不要求登录账号。后台账号用于记录和追溯，不再承担开发、测试线上审批。

## 启动

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

管理员创建项目、记录账号，并在项目成员中分配“记录人员”角色。旧业务角色保留查看权限，不自动获得录入权。超级管理员可代录；归档项目只读。

## 模块与规则

- 工作总览：进行中的需求、待补聊天证据、待核对运营数据、资产到期提醒与最近记录。
- 需求管理：业务进度与材料齐全分别统计；默认仅追加日志，可明确选择同步更新环节、负责人和版本。返工开启新轮次，旧记录不覆盖。业务发生时间与系统录入时间分开保存。
- 确认材料：按环节、轮次、版本保存截图与文档。只有明确确认人、结论、摘要并核对截图后才计为材料完整；上传截图不等于确认通过。完成后可以补历史环节材料。
- Bug 记录：不限需求环节；登记线下修复、回归、关闭及重开结果，保存提供人、版本、实际处理时间和历史快照。
- 版本与审查：人工登记发现、风险、复现情况及后续反馈；建议与决定分别留存，未自动连接代码仓库。
- 运营数据：项目＋统计日＋渠道唯一；接口推送与人工补录保留来源。只有已核对数据计入汇总，空值不是零。更正要求原因；接口差异保留原数值并进入核查。
- 波动复盘：原始两时点数据不覆盖，追加核查意见；不自动推断因果或定责。
- 资产与续费：登记域名、服务器、账号标识与用途；核实办理结果后才延长到期日，保存续费历史。
- 报告中心：固定预览快照、归档、中文 PDF、Excel、CSV 和原始附件包。后续业务变更不覆盖报告内容。

截图单张最多 5 MB；文档每份最多 20 MB。附件下载校验项目权限，禁止公开 `media/`。网页保留 CSRF 校验；数据推送接口采用独立项目 Token。

## 升级与接口

完整安装及 Nginx 部署见 [安装文档](docs/安装文档.md)。本次迁移、权限变化、数据接入协议及验收说明见 [记录人员版实施说明](docs/记录人员版实施说明.md)。

现有需求、Bug、账号和附件保留；迁移会从历史账号回填业务姓名，不把旧附件自动视为已核对证据。`seed_demo` 是旧版流程演示工具，不建议用于本版验收或生产数据库。

外部运营系统尚未指定，因此本版提供真实的入站推送接口及同步日志。外部平台需按协议推送，系统不会自行定时读取未知平台数据。

## 验证

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test tracker
```

测试覆盖记录员权限、跨项目隔离、追加与返工、材料核对、Bug 历史、日报去重及更正、续费、报表快照及导出、API 幂等与差异、页面提交和 CSRF。
